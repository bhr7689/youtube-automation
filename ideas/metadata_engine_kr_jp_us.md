## 0. 경험자 결론 — 스택은 갈아엎지 말 것

브리프는 "React+Node로 새로 만들라"고 했지만, 사장님 자산은 **Python(FastAPI/Streamlit)** 이다.
새 스택으로 재작성 = 기존 70% 폐기. **기존 `jpshorts` 백엔드 + 정적 HTML 위에 탭 하나로 얹는다.**

핵심: **이 엔진의 부품 대부분이 이미 존재**한다. 새로 만들 건 "국가별로 묶는 오케스트레이션 +
SERP 검증 + 3세트 패키지 화면"뿐이다.

## 2. ⭐ 썸네일을 제목과 일치시키는 법 (사장님 질문의 답)

이미 `concept_maker`에 **"제목과 썸네일은 한 세트"** 철학이 구현돼 있다. 그대로 엔진에 연결한다.

### 원리 5단
1. **한 몸 생성** — 제목·`thumb_text`(썸네일에 얹을 문구)·`image_prompt`(씬)를
   **한 번의 호출에서 같이** 만든다. 따로 만들지 않으니 어긋날 수가 없다.
   (concept_maker `title_sets` = [{title, thumb_text, image_prompt}] ×N)
2. **패턴 접지(SERP 실측)** — 그 나라 고조회 썸네일 상위 N개를 **GPT Vision**으로 실측
   (색·구도·인물·헤어·텍스트 오버레이·무드) → 그 패턴을 `image_prompt`에 주입.
   생성 썸네일이 **그 나라 터지는 썸네일 풀과 같은 결**이 된다. (`analyze_thumbnails_vision`)
3. **역할 분담** — 제목 = **검색형**(핵심 키워드 앞배치, 검색 유입) ·
   썸네일 문구 = **후킹형**(호기심 한 방). 둘이 같은 소재를 다른 각도로 = 일치하되 중복 아님.
4. **무드 이식 생성** — `generate_thumbnail_image(refs=상위 썸네일)` → `images.edit`로
   그 나라 색감·조명·필름결을 85% 흡수(구도 복제 금지, 새 씬 15%).
5. **한글 깨짐 방지** — 문구는 GPT가 이미지에 새기되, 최종 보정은 `thumb_overlay.overlay_title`
   (PIL 로컬 렌더)로 폰트 통일·깨짐 0.

### 무가사 음악 채널 특화
- 제목도 썸네일도 **"언제·왜 듣는지"(용도)를 앞세운다** — 아티스트 브랜딩 X, 검색의도 O.
- KR: 아늑한 씬(카페·새벽·창가) + "집중이 되는" 류 상황 문구
- JP: 作業机·手元·文房具 씬 + "作業用BGM/勉強用" 관용 문구
- US: cozy desk/rain window 씬 + "Deep Focus / No Lyrics" use-case 문구
- → 국가별로 **씬·문구·화풍이 다른** 3장의 일치 썸네일이 나온다.

### 피드백 루프
업로드 후 성과(CTR·조회속도)로 **제목·썸네일 재생성** — 한 번 만들고 끝이 아니라 재학습.

## 3. 핵심 알고리즘 (브리프 점수식을 기존 로직에 매핑)

### Keyword Quality Score (저품질 키워드 자동 탈락)
`keyword_radar` 에 품질 점수 추가:
```
KQS = 상위10 평균조회 ×0.35 + (상위10 조회/업로드일) ×0.25
    + 3개국 확장성 ×0.15 + 무가사 적합도 ×0.15 - 신생저조회 점유율 ×0.10
```
→ "검색하면 신생 저조회만 뜨는 키워드"는 KQS 미달로 **버림**. (사장님이 겪은 문제 해결)

### Title / Video Trend Score
`viral_lab`·`tier_lab`의 배수·구간 로직 재사용 + 브리프 가중치로 랭킹.

## 4. SERP 검증 (유일한 실질 신규 — Playwright)

- **시크릿 세션**(로그인·이력 제거) + **국가 locale/프록시**로 실제 검색 화면 캡처
- 상위 10개 썸네일·조회수·업로드일·채널 수집 → **경쟁 강도** 계산
- 판정: *"내 제목으로 검색 시 상위가 고조회·최신·강채널인가?"* → Yes 채택 / No 자동 재작성
- ⚠️ **웹 컨테이너는 유튜브 프록시 차단** → SERP 검증은 **사장님 PC(Playwright 로컬)** 에서 작동.
  API 1차 분석은 컨테이너/cron 가능, 브라우저 2차 검증은 PC.
- 참고: Chromium 이 이미 설치돼 있음(`/opt/pw-browsers`), 코드만 붙이면 됨.

## 5. 화면 구조 (기존 스타일 유지)

- **좌**: 곡 정보 입력(장르·무드·악기·BPM·길이·용도)
- **상단 탭**: 🇰🇷 KR / 🇯🇵 JP / 🇺🇸 US
- **중앙**: 트렌드 키워드 → 상위 영상 패턴 → 제목 후보(검색형5·추천형5) → 설명글 → **일치 썸네일 미리보기**

## 부록 A. 시작점 — "여름 재즈 플레이리스트" 수동 워크플로 → 엔진 규칙

> 이 프로젝트의 발단: 사장님이 `playlist | 시원한 수박 달콤 청량한 여름 재즈`로 검색 →
> URL이 키워드로 쪼개지는 걸 보고 "고조회 검색어를 역설계해 **내 영상을 고조회 영상 옆
> (연관 동영상)에 붙이자**"를 깨달음. Gemini와 수동으로 하던 것을 **엔진이 자동화**한다.
> **채널 정체성 확정: 무가사 여름/계절 재즈·BGM 플레이리스트 채널.**

### A-1. 핵심 목표 (엔진 판정 기준)
**"내 제목·썸네일이 그 나라 고조회 영상들과 같은 키워드 풀·같은 비주얼 톤에 묶이는가?"**
→ Yes면 채택, No면 재작성. (= SERP 검증 탭의 판정과 동일)

### A-2. 제목 공식 (상위권 벤치마킹에서 추출)
```
Playlist | [감성 훅 + 과일/계절 이모지] [형용사] [계절] 재즈 | [영문 use-case] BGM
예) Playlist | 시원한 수박 한 입 🍉 달콤하고 청량한 여름 재즈 | Summer Jazz BGM
```
- 맨 앞 `Playlist`/`[Playlist]` → 알고리즘이 플레이리스트로 분류
- 대표 이모지(🍉🍋🌊🍑🍹) → CTR
- 한글 키워드 + 영문 키워드 **반반** → 국내·글로벌 노출 동시
- 검색형(키워드 앞배치) / 추천형(감성 훅) 2계열 각 5개

### A-3. 제목 ↔ 썸네일 일치 (사장님이 직접 검증한 원리)
- 제목의 소재 = 썸네일의 그림 (수박 제목 ↔ 수박 일러스트) → 직관성·CTR ↑
- 썸네일 스타일 갈래: ①실사 청량컷(얼음물 과일) ②종이질감 콜라주 일러스트("A Good Day"류)
  ③여름 풍경(바다·정원·카페). 굵은 영문 폰트(Summer Jazz) 중앙/좌하단.
- **모바일 가독성**: 밝은 글씨는 아이보리 배경에 묻힘 → 그림자/외곽선 또는 진한 톤(딥그린·레드·브라운)
- → concept_maker `thumb_text` + `_overlay_prompt` + `thumb_overlay`(외곽선·그림자)로 자동 반영

### A-4. 설명글 4단 (그대로 매핑)
1. 감성 훅 1문장 (이 음악이 어떤 상황용인지 — "한 입 베어 물면 시원해지는 수박처럼")
2. 핵심 설명 (장르·분위기·무가사)
3. 사용 맥락 (일할 때·공부·카페·매장 BGM·드라이브·휴식)
4. + `[Tracklist]` 타임스탬프 + CTA(구독/플리)

### A-5. 태그·해시태그 정책
- 해시태그 **3~5개**, 한/영 반반 (`#여름재즈 #SummerJazz #청량한음악 #수박재즈 #카페BGM`)
- 태그: 한글(여름 재즈·플리·시원한 음악) + 영문(Summer Jazz Playlist) + 소재(수박) + use-case(공부할때 듣는 음악)

### A-6. 국가별 관용어 (엔진 국가 탭에 시드)
| | 강한 축 | 대표 관용어 |
|---|---|---|
| 🇰🇷 KR | 상황+감성 | 시원한·청량한·달콤한·새벽 감성·카페·매장 BGM |
| 🇯🇵 JP | 사용 장면+BGM 관용+**서양감성** | **作業用BGM**·勉強用BGM·睡眠用·癒し·集中·カフェ·スイカ(카타카나)·**洋楽**·**洋楽ジャズ** |
| 🇺🇸 US | use-case first | Deep Focus·No Lyrics·for Work/Study/Sleep·Chill·Ambient |
→ 카타카나(スイカ·ジャズ·BGM) + 영문(Summer Jazz·Playlist) 혼용이 일본에서 유리.

**🇯🇵 일본 승리 공식 = 用途 + 洋楽 + 시즌 3박자** (엔진 JP 탭 기본 조합):
```
用途(作業用BGM/勉強用) + 장르·감성(洋楽ジャズ/爽やかな) + 시즌·컨셉(スイカ/夏)
예) Playlist | 冷たいスイカをひと口 🍉 甘くて爽やかな洋楽夏のジャズ 作業用BGM | Summer Jazz

```

### A-7. 계절/컨셉 로테이션
과일·계절 컨셉을 소재축으로 순환(수박🍉/레몬🍋/복숭아🍑/바다🌊/풋사과🍏/메론소다🍹) →
같은 채널에서 컨셉별 제목·썸네일 세트를 계속 찍어내되 톤앤매너 유지(채널 정체성).

## ⭐⭐ A-8. 최우선 규칙 — 검색어 밀도형 제목 (사장님 지시: "잊지마")

> 출발점 체인: **Gemini에서 이 원리 발견 → 젠스파크로 가져가 대시보드 브리프화.**
> 이 규칙이 엔진 제목 생성의 **1순위 기본값**이다. 절대 잊지 않는다.

### 원칙: 감성 문장 < 실제 검색어 밀도
유튜브 검색 로봇은 **"문장의 감성"이 아니라 "유저가 실제 검색한 단어가 제목에 얼마나 정확히
들어있나(키워드 매칭/밀도)"** 를 먼저 평가한다. → **성장기 채널은 무조건 "검색어 나열형"(옵션2).**

| | 옵션1 문장형 감성 | **옵션2 검색어 밀도형 ✅ (기본값)** |
|---|---|---|
| 예(JP) | `冷たいスイカをひと口`(예쁘지만 검색 안 함) | `作業用・勉強用・カフェBGM`(실제 치는 단어) |
| 용도 | 이미 큰 채널의 브랜딩 | **대형 영상 연관추천에 묶여 빠른 성장** |

### 왜 이기나 (3이유 — 엔진 판정 근거)
1. **키워드 밀도** — 유저가 검색창에 실제 치는 단어를 제목에 촘촘히 (감성 문장 X)
2. **목적성 키워드 검색량** — 🇯🇵 3대장 `作業用BGM`·`勉強用BGM`·`カフェBGM` (수십만~수백만/일)
   반드시 포함 → 같은 조합 쓰는 대형 인기영상의 연관추천 풀에 진입
3. **카타카나·영문 시각 직관** — `BGM`·`Music`·`ジャズ`를 0.1초에 스캔·클릭

### 엔진 반영 (제목 생성 규칙)
- **검색형(밀도형) 제목을 1순위 기본**으로 생성. 추천형(감성)은 보조.
- 제목에 그 나라 **목적성 키워드(용도) + 장르 + 시즌**을 `・`(일본 중점)/공백으로 나열.
  예) `[Playlist] 暑い夏に聴きたい爽やかなジャズ 🍉 作業用・勉強用・カフェBGM | Summer Jazz Music`
- KQS(키워드 품질점수)에 **"실제 검색량·상위영상 재등장 빈도"** 가중 → 감성어보다 검색어 우선.
- 🇰🇷 KR도 동일: 감성 문장보다 `집중 음악·공부할 때 듣는·카페 BGM` 같은 실검색어 밀도 우선.
- 단, **키워드 스팸 금지선**(YouTube 정책) 지킴 — 오해성·과도 반복은 불이익. 자연스러운 밀도.

## ⭐⭐⭐ A-9. 본질 목표 — 시크릿 SERP 검증 → 최적화 루프 (엔진의 심장)

> 사장님 본질 목표(원문): "각 나라별 제목을 **시크릿 모드에서 검색했을 때 고조회 영상들이
> 뜨는지 확인**해야 한다. 어떤 제목은 **신생 채널 저조회 영상만** 떴다 — 이 부분이 가장 중요.
> 내 영상 제목을 **고조회 영상들과 묶이게 최적화**해 가는 것. **빠른 성장이 목표.**"

이 검증 루프가 엔진의 **최종 판정자**다. 제목 생성은 후보 제작일 뿐, **채택은 SERP가 결정한다.**

### 루프
```
후보 제목(검색어 밀도형)
  → 그 나라 locale 시크릿 브라우저로 검색
  → 상위 10~20개 수집(썸네일·조회수·업로드일·채널구독·채널나이)
  → 판정
       ❌ 신생·저조회 채널이 상위를 차지 → 탈락(약한 검색어)
       ✅ 고조회·강채널·최신이 상위      → 채택(고조회 풀에 묶임)
  → 탈락 시: 어느 키워드가 저조회를 끌었는지 분석 → 교체·강화 → 재생성 → 재검증
  → 곡당 최대 K회 반복, 최고 점수 채택
```

### 판정 지표 (핵심 = "신생 저조회 점유율")
- 상위N **중앙값 조회수**(median) — 절대 규모
- 상위N **조회/업로드일**(view velocity) — 최신성·속도
- **강채널 비율** — 구독 임계 이상 채널 %
- 🚫 **신생 저조회 채널 점유율** — 구독↓ & 조회↓ % → **이게 높으면 탈락** (사장님이 겪은 그 문제)
- **내 핵심 키워드 재등장 빈도** — 상위 제목에 내 키워드가 있나(= 내가 그 풀 소속인가)
```
SERP Fit = median_views·0.30 + view_velocity·0.25 + 강채널비율·0.20
         + 키워드재등장·0.15 - 신생저조회점유율·0.30   (음수 가중이 킬러)
임계 미달 → 자동 재작성.
```

### 실행 구조 (정직한 기술 현실)
- **시크릿 모드**는 *개인화 이력*만 제거한다. **지역·언어·브라우저는 여전히 결과에 영향** →
  국가별 **locale(hl/gl) + 가능하면 프록시/VPN**를 태워야 KR/JP/US 실제 화면에 근접.
- ⚠️ **YouTube Data API `search.list` ≠ 실제 브라우저 SERP** (API는 개인화 없음·랭킹 다름).
  → **진짜 검증은 반드시 Playwright 시크릿 브라우저**로 실제 검색 화면을 캡처·파싱해야 한다.
- **2단 구조**:
  1. **1차(클라우드/cron 가능)** — API로 후보 키워드·제목 대량 스코어링(싸고 빠름)
  2. **2차(진짜 판정 — 사장님 PC)** — Playwright 시크릿+locale로 실제 SERP 캡처 → 위 판정
     · 웹 컨테이너는 유튜브 프록시 차단 → 2차는 PC에서. Chromium은 이미 설치됨(`/opt/pw-browsers`).
- 산출물: 각 후보 제목마다 **SERP 스냅샷(상위10 썸네일·조회·채널) + Fit 점수 + 채택/탈락 사유.**

### 신규 코드
- [ ] `serp_probe.py` — Playwright 시크릿 + 국가 locale/프록시 → 상위N 파싱(조회·업로드일·채널)
- [ ] `serp_judge.py` — 위 판정 지표·Fit 점수(순수 로직, 데모/목으로 검증 가능)
- [ ] 최적화 루프 — 탈락 키워드 분석 → 재생성 → 재검증(곡당 K회), `metadata_engine`에 연결
- [ ] 화면: 후보별 SERP 스냅샷 + Fit 배지 + 채택/탈락 사유 + 🔄 자동 재작성 로그

## ⭐⭐ A-10. 알고리즘 변화 적응 — "공식은 고정, 재료는 유동" (trend_meta)

> 사장님 질문: 알고리즘은 시기별로 변한다. 때로는 과일, 때로는 카페 분위기가 뜬다.
> 이럴 때 어떻게 대응하나? → **컨셉을 하드코딩하지 않는다.**

| 층 | 성격 | 예 |
|---|---|---|
| **공식(FORMULA)** 고정 | 밀도형 제목·3계층 키워드·SERP 판정 | 안 바뀜 |
| **재료(INGREDIENTS)** 유동 | 지금 뜨는 컨셉축(과일/카페/비/난로) + 그 시기 실검색어 | 계속 갱신 |

### 3가지 적응 신호 (`trend_meta.py`)
1. **트렌드 하베스트** — 현재 상위 영상 제목에서 반복 테마 추출(`extract_hot_themes`) +
   뜨는 일반 키워드 추출(`extract_rising_terms`) → `trend_meta.json` 갱신(cron 공유).
2. **SERP 판정 = 적응 신호** — 과일 제목이 SERP에서 신생 저조회만 끌면(`verdict=regenerate`)
   = 그 테마가 식은 것 → **다른 뜨는 테마로 교체** 재생성(`theme_stale_signal`).
3. **계절 프라이어(폴백)** — 라이브 데이터 없을 때만 쓰는 약한 사전지식
   (여름→과일/바다, 가을·겨울→카페/비/난로). `SEASONAL_PRIOR`.

### 엔진 연결
- `metadata_engine.generate_adaptive(country)` — trend_meta가 고른 **지금 뜨는 테마**를
  같은 공식에 슬롯 + 뜨는 실검색어를 3계층 감성/상황에 주입.
- 새 테마(카페/비/새벽/난로)는 **코드 변경이 아니라 데이터 1줄 추가**로 확장(= 적응 설계).
- 검증: 여름 상위제목→'수박' 감지 / 가을 상위제목→'카페'로 자동 이동. 같은 공식이
  `[Playlist] 포근한 카페 재즈 ☕ 공부할 때·일할 때·카페 BGM | Cafe Jazz` 처럼 그대로 통함.

- [x] `metadata_engine.generate_adaptive` — 지금 뜨는 테마 자동 슬롯 + 태그 boost

## ⭐⭐⭐ A-11. 전문가 팀 구조 — "한 명이 다" → "10명 전문가 + 편집장" (metadata_team)

> 사장님 통찰: 직원 1명이 전부 하는 것보다, 전문가 10명이 자기 분야만 세밀하게 파고
> 편집장이 하나로 정리하면 **결과물의 깊이(전문성)·넓이(다차원)** 가 달라진다.

기존 `metadata_engine`(만능 1인) → **전문가 팀 파이프라인**으로 재배치. 공유 `Brief`(작업지시서)를
순서대로 흘리며 각 전문가가 자기 파트를 깊게 채우고, 편집장이 종합 + QA + 최종 복붙 패키지.

### 전문가 명단 (`metadata_team.py`)
| # | 전문가 | 전문 분야 | 기반 |
|---|---|---|---|
| 1 | 🧭 트렌드 애널리스트 | 지금 뜨는 테마축 결정 | trend_meta |

| 3 | 🕵️ 경쟁/SERP 분석가 | 상위 패턴 + SERP 판정(채택/재작성) | serp_judge |
| 4 | ✍️ 제목 카피라이터 | 밀도형/감성형 제목 | generate_titles |
| 5 | 📄 설명글 SEO 작가 | 4단 + 상단 키워드 밀도 | build_description |
| 6 | 🏷️ 태그·해시태그 전략가 | 3계층 태그 + 해시태그 3~5 | build_tags |

### 지금 vs 앞으로(심화)
- **지금**: 규칙기반으로 10명이 동작 + 편집장 종합 + QA 점수(self-test 통과).
- **심화(키 연결 시)**: 각 전문가를 **LLM 페르소나**로 격상(깊은 프롬프트) — 키워드 리서처는
  실검색량·자동완성까지, 카피라이터는 수백 후보 생성, QA는 lyrics_evaluator식 재작업 지시.
- **재작업 루프**: QA/SERP가 임계 미달이면 편집장이 해당 전문가에게 **되돌려 재작업**(반복).

### 왜 결과가 달라지나
- 넓이: 트렌드·키워드·경쟁·제목·설명·태그·썸네일·현지화·정책·QA **10개 축**을 각각 커버.
- 깊이: 각 전문가가 자기 분야만 파므로 디테일↑ + 서로 검증(경쟁분석·정책·QA가 교차 견제).
- 산출: 팀 리포트(누가 뭘 했는지) + 최종 복붙 패키지 + QA 점수·플래그 = 신뢰도 가시화.
